## Обзор

При работе **Antigravity** выполняет shell-команды, изменяет файлы и обращается к сети. Запуск напрямую создает риски для хоста из-за ошибок модели или галлюцинаций.

**Antigravity Sandbox** изолирует агента внутри Docker-контейнера через спецификацию Dev Containers, решая три ключевые задачи:

* **Изоляция файловой системы:** агент ограничен рабочей директорией проекта внутри контейнера и не имеет доступа к файлам хоста (`~/.ssh`, токенам, переменным окружения и системным каталогам).
* **Блокировка доступа к локальной сети (LAN):** стандартный Docker bridge не изолирует локальную сеть хоста. В проекте сетевой периметр защищен на уровне ядра с помощью правил `iptables` и `ip rule` (через systemd-сервис), что исключает сканирование и доступ к локальным ресурсам (роутерам, NAS, другим машинам).
* **Чистота хост-системы:** все зависимости, пакетные менеджеры и временные файлы остаются внутри контейнера, не засоряя основную ОС.

Состояние сессий, история диалогов и авторизационные токены Antigravity сохраняются в выделенных Docker-томах (volumes), не смешиваясь с файлами пользователя.

## Системные требования к хосту

Перед развертыванием Antigravity Sandbox убедитесь, что хост-система удовлетворяет требованиям:

* **Операционная система:** Linux с поддержкой ядерного стека RPDB (Routing Policy Database / `ip rule`) и Netfilter (`iptables` и `ip6tables`).
* **Контейнерный движок:** Docker Engine (20.10+) с поддержкой Docker Buildx (для воспроизводимых сборок с хэш-пиннингом зависимостей).
* **Системные утилиты хоста:** `iproute2` (`ip rule`, `ip route`), `iptables`, `jq`, `git` (2.20+) и `systemd` (для демона постоянной сетевой изоляции).
* **Привилегии:** Административные права (`sudo`) требуются только для настройки сетевого моста хоста и установки systemd-сервиса. Для повседневной разработки внутри контейнера root-права не нужны.

### Реализация защиты

- **Выделенные цепочки Netfilter (`AGY-SANDBOX-FWD` и `AGY-SANDBOX-IN`):** Фильтрация трафика инкапсулирована в отдельные цепочки, привязанные к `DOCKER-USER` и `INPUT`. Транзитный трафик из моста контейнеров `agy0` во все приватные и спецдиапазоны IPv4 (RFC 1918, CGNAT `100.64.0.0/10`, link-local `169.254.0.0/16`, loopback, multicast, testnets) безусловно сбрасывается (`DROP`). Слушающие порты хоста (SSH, БД, демон Docker) блокируются через `AGY-SANDBOX-IN`, разрешая только DNS хоста (порт 53 UDP/TCP) и установленные сессии (`ESTABLISHED,RELATED`).
- **Защита Fail-Closed (маркер готовности):** Запуск контейнеров строго требует полностью поднятой и изолированной сети хоста. Скрипт `ensure-network.sh` создает маркер `/run/agy-sandbox/network.ready` только после успешного применения и проверки всех правил Netfilter и RPDB. Как CLI-инициализатор (`init-sandbox.sh`), так и директива `initializeCommand` в Dev Container прерывают запуск в режиме Fail-Closed, если маркер или правила маршрутизации отсутствуют.
- **Двухуровневая маршрутизация политик ядра Linux (RPDB):** Правила маршрутизации строго привязаны к входящему интерфейсу (`iif agy0`), что гарантирует защиту от утечек трафика даже при активных split-tunnel VPN, переопределяющих таблицу main хоста. Трафик внутри подсети разрешается с приоритетом 95 (`lookup main`), а любые обращения к приватным CIDR назначения сбрасываются с приоритетом 100 (`unreachable`).
- **Предсобранный оффлайн-патчер и Supply Chain Pinning:** При сборке Docker-образа внешние зависимости фиксируются неизменяемыми хэшами (`ghcr.io/astral-sh/uv` по sha256, `QNIX-Dev/eligibility-antigravity-patcher` по коммиту `90498f50353d414232f593dffe88899bc80b6312`). Патчер предварительно устанавливается в защищенный системный каталог `/usr/local/share/agy-sandbox/patcher` (владелец `root:root`). При старте контейнера `setup.sh` применяет патчер полностью автономно без `git clone` и без доступа к сети.
- **Блокировка проброса учетных данных хоста:** В Dev Container принудительно зафиксированы `dev.containers.copyGitConfig: false`, `dev.containers.dockerCredentialHelper: false`, `git.terminalAuthentication: false`, `github.gitAuthentication: false`. В `remoteEnv` переменные `SSH_AUTH_SOCK`, `VSCODE_GIT_IPC_HANDLE` обнулены, а хелперы askpass перенаправлены на `/bin/false`. При каждом старте контейнера очищаются проброшенные сокеты аутентификации.
- **Харденинг systemd-сервиса:** Исполняемые скрипты и файл конфигурации копируются в каталог `/usr/local/lib/agy-sandbox/`, принадлежащий `root:root` с правами только для чтения (`0755`/`0644`), что исключает уязвимость локального повышения привилегий (LPE). Сервис запускается с параметрами изоляции `ProtectHome=yes`, `ProtectSystem=full`, `PrivateTmp=yes` и управляет рантайм-директорией `/run/agy-sandbox`.
- **Динамический Docker IPAM без конфликтов:** По умолчанию подсети выделяются автоматически штатным механизмом Docker IPAM из бесконфликтного пула (`172.17.0.0/16`-`172.31.0.0/16`), с возможностью явного принудительного задания статического CIDR через `sandbox.conf`.
- **Изолированный dual-DNS (`9.9.9.9`, `149.112.112.112`):** Запросы резолвятся напрямую через пару Quad9-серверов в обход резолвера хоста, что исключает утечки DNS и сканирование локальных хостов через NetBIOS/mDNS.
- **Сброс сетевых и системных привилегий:** Контейнер запускается с опцией `--security-opt=no-new-privileges:true` и сбросом capability `CAP_NET_RAW`, что исключает атаки на ядро, манипуляции с raw-сокетами, подмену ARP или крафт ICMP-пакетов.
- **Защита бинарника от модификации:** Для зафиксированных версий (`AGY_VERSION != latest`) права на `agy` фиксируются на чтение и выполнение (`chmod 555`), а автообновление блокируется переменной `AGY_CLI_DISABLE_AUTO_UPDATE=1`. При использовании версии `latest` сохраняются стандартные права (`chmod 755`) и штатные автообновления.
- **Двухуровневая модель хранения и изоляции:** Общая глобальная конфигурация (токены авторизации, общие настройки, ID инсталляции, конфиг MCP) сохраняется в постоянном Docker-томе (`agy-shared-config -> /home/vscode/.gemini-shared`), исключая необходимость повторной авторизации при создании новых песочниц. Проектный контекст (история диалогов, граф brain, локальные базы и кэши) сохраняется в изолированном для каждого проекта томе (`agy-gemini-data-${localWorkspaceFolderBasename} -> /home/vscode/.gemini`). Скрипт `setup.sh` связывает файлы общей конфигурации симлинками при запуске.
- **Защита конфигурации `.devcontainer`:** Каталог `.devcontainer` монтируется внутрь контейнера исключительно в режиме Read-Only (`type=bind,readonly`), исключая изменение скриптов инициализации и настроек контейнера изнутри запущенной песочницы.

## Быстрый старт: подключение к проекту

### Инициализатор agy-sandbox (TUI / CLI)

Развертывание песочницы в целевом репозитории:

```bash
# Клонировать репозиторий песочницы
git clone https://codeberg.org/Retr0xCC/antigravity-sandbox.git ~/.antigravity-sandbox

# Установить команду 'agy-sandbox' в ~/.local/bin
~/.antigravity-sandbox/scripts/init-sandbox.sh --install-bin

# Интерактивный режим (TUI):
agy-sandbox

# Либо инициализация напрямую через аргументы:
agy-sandbox /path/to/project
agy-sandbox /path/to/project [шаблон]
agy-sandbox /path/to/project [шаблон] -v 1.4.6
```

#### Режим изоляции Git Worktree (`--worktree`)

При разработке в существующих репозиториях предоставление автономному агенту прямого доступа на запись в рабочее дерево проекта несет существенные риски: галлюцинирующая или скомпрометированная модель может изменить сборочные скрипты, конфигурации или git-хуки, которые затем могут быть запущены разработчиком на хосте.

Флаг `--worktree` обеспечивает полную изоляцию на уровне файловой системы с помощью связанных рабочих деревьев Git (git worktrees):

* **Отдельный каталог песочницы:** Инициализатор автоматически создает изолированный git worktree рядом с основным репозиторием (`<repo>-sandbox`) на отдельной ветке (по умолчанию: `agy-sandbox`, настраивается через `--worktree-branch <ветка>`).
* **VFS Read-Only защита метаданных Git:** Внутри worktree Git обращается к общей родительской директории `.git`. Песочница монтирует общую директорию `.git` и накладывает VFS Read-Only bind-маунты ядра Linux непосредственно на `.git/hooks`, `.git/config` и `.git/info`. Это физически блокирует попытки контейнера внедрить вредоносные Git-хуки (например, `pre-commit`) или изменить конфигурацию Git для исполнения кода на хосте.
* **Исключение конфигурации:** Каталог `.devcontainer/` автоматически добавляется в `${main_git_dir}/info/exclude`, благодаря чему конфигурация контейнера не отображается в `git status` и случайно не попадает в коммиты.
* **Рекомендуемый рабочий процесс (Workflow):**
  1. Инициализируйте песочницу: `agy-sandbox --worktree /path/to/project`
  2. Откройте директорию worktree: `code /path/to/project-sandbox`
  3. Переоткройте в контейнере (`F1` -> `Dev Containers: Reopen in Container`).
  4. Позвольте Antigravity выполнять задачи кодогенерации внутри контейнера.
  5. На хосте проверьте диффы через `git diff main..agy-sandbox`, запустите тесты и безопасно влейте ветку в основную.

#### Безопасные кастомные маунты (`--mount`)

Если для работы проекта требуются дополнительные датасеты или общие каталоги вне репозитория, используйте флаг `--mount` (можно указывать несколько раз):

```bash
# Режим по умолчанию: Read-Only (:ro)
agy-sandbox --mount /var/data/shared:/data:ro /path/to/project

# При пропуске режима автоматически применяется Read-Only с информационным уведомлением:
agy-sandbox --mount /var/data/shared:/data /path/to/project

# Явный режим чтения и записи (используйте осмотрительно):
agy-sandbox --mount /var/data/output:/output:rw /path/to/project
```

**Ограничения безопасности (Blacklist):**
Для предотвращения эскалации привилегий и компрометации хоста инициализатор строго запрещает монтирование:
* Корневой файловой системы (`/`);
* Системных каталогов хоста и любых их поддиректорий: `/etc`, `/usr`, `/var`, `/bin`, `/sbin`, `/lib`, `/lib64`, `/proc`, `/sys`, `/dev`, `/run`, `/root`;
* Сокетов демона Docker (`/var/run/docker.sock`, `/run/docker.sock`);
* Домашнего каталога пользователя (`$HOME`) целиком;
* Чувствительных каталогов внутри `$HOME`: `.ssh`, `.gnupg`, `.aws`, `.kube`, `.config`, `.docker`, `.local` (и любых их поддиректорий).
Попытка указать запрещенный путь немедленно прерывает выполнение с фатальной ошибкой безопасности.

#### Фиксация версий Antigravity CLI и патчинг

По умолчанию песочницы развертываются с зафиксированной стабильной версией CLI (`1.4.6`), что исключает непредвиденные поломки из-за обновлений upstream, и применяют патч `QNIX-Dev`.

* **Единая переменная управления (`AGY_VERSION`):** Переменная `AGY_VERSION` выполняет обе функции — задает установленный бинарник и активирует режим безопасности. При фиксации версии (`AGY_VERSION != latest`) песочница автоматически защищает бинарник от перезаписи (`chmod 555`) и отключает автообновления (`AGY_CLI_DISABLE_AUTO_UPDATE=true` в `~/.bashrc`). Для версии `latest` сохраняются стандартные права (`chmod 755`) и штатное автообновление.
* **Опциональный патчинг:** Передайте `--no-patch` (или выберите `No` на шаге 4 мастера TUI), чтобы использовать чистый официальный бинарник без сторонних модификаций. Флаг `--patch` принудительно включает патчинг.
* **Постоянная настройка по умолчанию в `base/devcontainer.json`:** Чтобы перманентно изменить дефолтную версию или состояние патчинга для всех будущих песочниц, достаточно отредактировать файл `base/devcontainer.json` (`build.args.AGY_VERSION`, `remoteEnv.AGY_VERSION` и `remoteEnv.AGY_PATCH`). Инициализатор считывает значения по умолчанию напрямую из этого файла.
* **Интерактивный TUI и CLI:** Мастер позволяет интерактивно выбрать версию (`1.4.6`, `latest`, произвольный тег) и включить/выключить патчер. В CLI доступны флаги `-v, --agy-version <тег>` и `--no-patch`.

Доступные профили шаблонов:
- `default` (по умолчанию) — Базовое чистое окружение: antigravity-cli, uv, git и стандартный набор утилит сборки.
- `rpi-edge-node` — Профиль для автоматизации граничных узлов и шлюзов с Ansible (2.15+), `ansible-lint`, `yamllint`, коллекцией `community.general`, Go (1.22+), клиентом OpenSSH и расширениями VS Code (`redhat.ansible`, `golang.go`, `redhat.vscode-yaml`, `even-better-toml`, `samuelcolvin.jinjahtml` для шаблонов Jinja2 `.j2`).
- `math-labs` — Профиль для математических вычислений и анализа данных с Python, Jupyter (`ms-toolsai.jupyter`), просмотрщиком PDF (`tomoki1207.pdf`), NumPy, SciPy, Matplotlib, SymPy и pandas.

## Настройка сетевой изоляции на хосте

Чтобы правила фильтрации (`nftables`/`iptables`) и маршрутизации (`ip rule`) автоматически поднимались при загрузке ОС, в проект включен systemd-сервис:

```bash
# Установить и активировать сервис в системе:
sudo agy-sandbox service install
sudo agy-sandbox service enable

# Проверить статус:
agy-sandbox service status

# При необходимости отключить правила:
sudo agy-sandbox service disable
```

### Конфигурация (`scripts/sandbox.conf` и переменные окружения)

Сетевой стек песочницы использует единый централизованный конфигурационный файл `scripts/sandbox.conf` как Single Source of Truth (SSOT). При установке в качестве системного сервиса файл копируется в `/usr/local/lib/agy-sandbox/sandbox.conf`.

| Переменная | Значение по умолчанию | Описание |
| :--- | :--- | :--- |
| `NETWORK_NAME` | `"agy_net"` | Имя Docker bridge-сети. |
| `BRIDGE_NAME` | `"agy0"` | Имя сетевого интерфейса моста ядра Linux. |
| `SUBNET` | `""` | CIDR подсети. Если строка пустая (`""`), Docker IPAM динамически выделяет свободную подсеть из пула `172.17.0.0/16`-`172.31.0.0/16`. Если задан CIDR (например, `"172.16.151.0/24"`), он применяется принудительно. |
| `DNS_PRIMARY` | `"9.9.9.9"` | Основной апстрим DNS-сервер (Quad9). |
| `DNS_SECONDARY` | `"149.112.112.112"` | Резервный апстрим DNS-сервер (Quad9). |
| `READY_FILE` | `"/run/agy-sandbox/network.ready"` | Путь к маркеру готовности сети (Fail-Closed). |
| `PIDS_LIMIT` | `"2048"` | Лимит количества процессов внутри контейнера (защита от fork-бомб). |
| `MEMORY_LIMIT` | `"8g"` | Максимальный объем оперативной памяти для контейнера. |
| `CPUS_LIMIT` | `"4"` | Максимальное количество процессорных ядер для контейнера. |
| `TMPFS_SIZE` | `"2g"` | Размер in-memory файловой системы `/tmp` (`rw,nosuid,nodev`). |

Все параметры в `sandbox.conf` могут быть переопределены через переменные окружения без прямой модификации файла:

```bash
# Пример 1: Установка сервиса с принудительной подсетью и альтернативным DNS
sudo SUBNET="172.16.200.0/24" DNS_PRIMARY="1.1.1.1" agy-sandbox service install
sudo agy-sandbox service enable

# Пример 2: Прямой запуск настройки сети с временными параметрами
sudo NETWORK_NAME="custom_net" BRIDGE_NAME="cbr0" /usr/local/lib/agy-sandbox/ensure-network.sh
```

### Харденинг systemd-сервиса и защита Fail-Closed

- **Защита от повышения привилегий (LPE):** При выполнении `sudo agy-sandbox service install` все скрипты и `sandbox.conf` копируются в `/usr/local/lib/agy-sandbox/`, принадлежащий пользователю `root:root` с правами доступа `0755`/`0644`. Системный юнит `agy-sandbox-network.service` вызывает скрипты исключительно из этой защищенной директории, исключая модификацию непривилегированным пользователем.
- **Песочница systemd:** Сервис выполняется с директивами `ProtectHome=yes`, `ProtectSystem=full`, `PrivateTmp=yes`, а рантайм-директорией `/run/agy-sandbox` управляет сам systemd.
- **Гарантии Fail-Closed:** Успешный запуск сети создает маркер `/run/agy-sandbox/network.ready` только после верификации всех правил фаервола и маршрутизации. CLI-инициализатор `agy-sandbox` проверяет наличие этого маркера перед сборкой devcontainer или запуском среды.

### Проверка сетевой изоляции

Для комплексного аудита правил Netfilter, таблиц маршрутизации и доступности DNS предусмотрен встроенный диагностический инструмент:

```bash
agy-sandbox diagnose
# Либо прямой запуск скрипта:
~/.antigravity-sandbox/scripts/diagnose.sh
```

Диагностика проверяет 8 комплексных контрольных точек безопасности:
1. **Docker Engine, сеть моста (`agy_net`) и маркер готовности:** Проверка отклика демона Docker, динамическое определение назначенной подсети, сопоставление интерфейса `agy0` и проверка наличия файла `/run/agy-sandbox/network.ready`.
2. **Сетевой интерфейс ядра (`agy0`):** Подтверждение существования интерфейса моста и его состояния в ядре.
3. **Маршрутизация политик ядра Linux (`ip rule`):** Проверка правила приоритета 95 для внутриподсеточного трафика (`lookup main`) и правил приоритета 100 `unreachable` для всех 12 приватных/специальных диапазонов IPv4, строго привязанных к интерфейсу `iif agy0`.
4. **Фильтрация пакетов Netfilter (`iptables` / `ip6tables`):** Проверка переходов в кастомные цепочки `AGY-SANDBOX-FWD` и `AGY-SANDBOX-IN`, внутриподсеточного правила `RETURN`, блокировок DROP для всех 12 диапазонов и ограничения доступа к хосту (разрешен только DNS на порту 53).
5. **Рубеж IPv6 и персистентность Systemd:** Аудит отключения IPv6 (`disable_ipv6` на `agy0`), доступность ip6tables и подтверждение неизменяемости файлов сервиса в `/usr/local/lib/agy-sandbox/`.
6. **Supply Chain Pinning и целостность образа:** Проверка неизменяемого sha256 хэша для `uv`, пиннинга коммита патчера, непривилегированных прав на тома, защищенного размещения скриптов в `/usr/local/share/agy-sandbox/` и поддержки `safe.directory` для git worktree.
7. **Спецификация Dev Container и рантайм-харденинг:** Статический аудит флагов блокировки учетных данных хоста, нейтрализации Askpass/IPC, Fail-Closed проверки `initializeCommand`, параметров безопасности `runArgs`, readonly-маунта `.devcontainer` и флагов CLI (`--worktree`, `--mount`).
8. **Проверка границ контейнера и активные зонды:** Инспекция запущенного контейнера (`no-new-privileges`, сброс capability `NET_RAW`, лимит pids), Read-Only маунтов метаданных Git (`hooks`, `config`, `info`) и зондирование сетевых рубежей TCP-сокетами без привилегий.

### Жизненный цикл контейнера (setup.sh)

Скрипт первичной настройки `setup.sh` предустановлен в системный каталог `/usr/local/share/agy-sandbox/setup.sh` и выполняется один раз при создании контейнера (`postCreateCommand`):
* выставляет корректные непривилегированные права на тома `/home/vscode/.gemini` и `/home/vscode/.gemini-shared`;
* безопасно регистрирует целевую рабочую директорию в `git config safe.directory`, корректно разрешая ссылки `gitdir:` в случае git worktree без использования небезопасных масок (`safe.directory "*"`);
* запускает автономный патчер `/usr/local/share/agy-sandbox/patcher/manager.py` полностью в оффлайн-режиме без скачивания внешнего кода;
* фиксирует бинарник от изменений (`chmod 555`) при зафиксированной версии или сохраняет `chmod 755` для `latest`;
* очищает проброшенные сокеты аутентификации и скопированные учетные данные хоста;
* создает маркер `/home/vscode/.agy_initialized`, предотвращая повторное выполнение при перезапусках.

## Модель безопасности и остаточные риски

### Что закрыто на 100% (Zero-Trust Guardrails)

Antigravity Sandbox реализует многоуровневую глубоко эшелонированную защиту:

| Вектор атаки | Механизм защиты | Уровень защиты |
| :--- | :--- | :--- |
| **Сканирование локальной сети (LAN) и интранета** | Маршрутизация ядра RPDB (`iif agy0` приоритет 100 `unreachable`) и Netfilter `AGY-SANDBOX-FWD` DROP | **100% Заблокировано** (на уровне ядра) |
| **Кража метаданных облака (`169.254.169.254`)** | Явный сброс маршрутов и фильтрация link-local диапазонов в firewall | **100% Заблокировано** |
| **Доступ к службам хоста (SSH, БД, Ollama, сокет Docker)** | Netfilter `AGY-SANDBOX-IN` DROP на интерфейсе `agy0` (разрешен только DNS на порту 53) | **100% Заблокировано** |
| **Утечка учетных данных хоста и сокетов авторизации** | Переопределение настроек VS Code (`copyGitConfig: false`, `dockerCredentialHelper: false`), обнуление askpass/IPC в `remoteEnv`, удаление сокетов при старте | **100% Нейтрализовано** |
| **Побег из контейнера и эксплуатация уязвимостей ядра** | `--security-opt=no-new-privileges:true`, `--cap-drop=NET_RAW`, непривилегированный пользователь `vscode`, лимиты pids/memory/cpus | **Защищено** |
| **Модификация конфигурации контейнера** | Read-Only bind-маунт каталога `.devcontainer/` внутрь контейнера | **100% Защищено** |
| **Атаки на цепочку поставок при сборке образа** | Фиксация digest `uv` (`sha256:32a...`), фиксация коммита патчера (`90498f50353d`), предсобранный оффлайн-патчер в `/usr/local/share/agy-sandbox/patcher` (root:root) | **100% Неизменяемо** |
| **Внедрение вредоносных Git hooks / Git config (режим `--worktree`)** | Ядерные VFS Read-Only bind-маунты на `.git/hooks`, `.git/config` и `.git/info` | **100% Защищено** (VFS Read-Only) |

### Остаточный риск (Прямое монтирование БЕЗ `--worktree`)

> [!WARNING]
> При запуске песочницы напрямую в основном репозитории хоста **без** флага `--worktree` контейнер имеет прямой доступ на запись в файлы вашего проекта.

Если проект содержит исполняемые файлы, сборочные скрипты или конфигурации IDE:
* `Makefile`, `build.sh`, `configure`
* `package.json` (`scripts`, `preinstall`, `postinstall`)
* `.vscode/tasks.json` или `.vscode/launch.json`
* Конфигурации сборки Python (`setup.py`, `pyproject.toml`)

Галлюцинирующий или скомпрометированный агент может модифицировать эти файлы внутри контейнера. Если вы впоследствии запустите команду `make`, `npm test` или выполните задачу VS Code на хост-системе вне песочницы, вредоносный код будет выполнен на хосте с вашими правами!

**Рекомендация и митигация:**
* Для непроверенного кода, внешних репозиториев, автономных запусков агента или чувствительных сред **ВСЕГДА используйте режим `--worktree`**:
  ```bash
  agy-sandbox --worktree /path/to/project
  ```
* В режиме `--worktree` любые изменения агента физически изолированы в каталоге `<repo>-sandbox` и отдельной ветке Git. Кроме того, хостовые `.git/hooks` и `.git/config` защищены VFS-маунтами в режиме «только чтение».
* Никогда не сохраняйте открытые боевые токены, `.env` файлы с продакшн-паролями или приватные ключи внутри рабочей директории проекта перед запуском песочницы.

## Создание собственных шаблонов

`antigravity-sandbox` поддерживает два формата создания шаблонов:

### 1. Декларативный режим (рекомендуется)

Вместо дублирования базовых файлов `Dockerfile` и `setup.sh`, достаточно создать каталог `templates/<имя_шаблона>/` только с необходимыми манифестами:

- **`packages.txt`** *(опционально)* — системные пакеты для установки через `apt-get` (по одному на строку, поддерживаются комментарии `#`).
- **`extensions.txt`** *(опционально)* — идентификаторы расширений VS Code (например, `golang.go`, `ms-python.python`).
- **`settings.json`** *(опционально)* — параметры конфигурации редактора, объединяемые с `customizations.vscode.settings`.
- **`extra.Dockerfile`** *(опционально)* — дополнительные сборочные инструкции для образа (например, `uv tool install ...`).
- **`extra-setup.sh`** *(опционально)* — bash-команды, выполняемые при первичной инициализации контейнера.
- **`description.txt`** *(опционально)* — краткое описание для справки CLI (`--list`) и меню TUI (по умолчанию: `Custom sandbox profile`).

Инициализатор песочницы автоматически наследует базовую конфигурацию (`base/Dockerfile`, `base/setup.sh`, `base/devcontainer.json`), объединяя её с манифестами шаблона.

### 2. Режим полной конфигурации (Full Custom Mode)

Если требуется полностью переопределить среду сборки, поместите собственные файлы `devcontainer.json` и/или `Dockerfile` напрямую в каталог `templates/<имя_шаблона>/`. Инициализатор скопирует их в целевой проект без объединения с базовым слоем.
