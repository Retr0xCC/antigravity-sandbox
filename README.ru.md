## Обзор

При работе **Antigravity** выполняет shell-команды, изменяет файлы и обращается к сети. Запуск напрямую создает риски для хоста из-за ошибок модели или галлюцинаций.

**Antigravity Sandbox** изолирует агента внутри Docker-контейнера через спецификацию Dev Containers, решая три ключевые задачи:

* **Изоляция файловой системы:** агент ограничен рабочей директорией проекта внутри контейнера и не имеет доступа к файлам хоста (`~/.ssh`, токенам, переменным окружения и системным каталогам).
* **Блокировка доступа к локальной сети (LAN):** стандартный Docker bridge не изолирует локальную сеть хоста. В проекте сетевой периметр защищен на уровне ядра с помощью правил `iptables` и `ip rule` (через systemd-сервис), что исключает сканирование и доступ к локальным ресурсам (роутерам, NAS, другим машинам).
* **Чистота хост-системы:** все зависимости, пакетные менеджеры и временные файлы остаются внутри контейнера, не засоряя основную ОС.

Состояние сессий, история диалогов и авторизационные токены Antigravity сохраняются в выделенных Docker-томах (volumes), не смешиваясь с файлами пользователя.

## Системные требования к хосту

Перед развертыванием Antigravity Sandbox убедитесь, что хост-система удовлетворяет требованиям:

* **Операционная система:** Linux с поддержкой ядерного стека RPDB (Routing Policy Database / `ip rule`) и Netfilter (`iptables` и `ip6tables`).
* **Контейнерный движок:** Docker Engine (20.10+) с поддержкой Docker Buildx (для воспроизводимых сборок с хэш-пиннингом зависимостей).
* **Системные утилиты хоста:** `iproute2` (`ip rule`, `ip route`), `iptables`, `jq`, `git` (2.20+) и `systemd` (для демона постоянной сетевой изоляции).
* **Привилегии:** Административные права (`sudo`) требуются только для настройки сетевого моста хоста и установки systemd-сервиса. Для повседневной разработки внутри контейнера root-права не нужны.

### Реализация защиты

- **Выделенные цепочки Netfilter (`AGY-SANDBOX-FWD` и `AGY-SANDBOX-IN`):** Фильтрация трафика инкапсулирована в отдельные цепочки, привязанные к `DOCKER-USER` и `INPUT`. Транзитный трафик из моста контейнеров `agy0` во все приватные и спецдиапазоны IPv4 (RFC 1918, CGNAT `100.64.0.0/10`, link-local `169.254.0.0/16`, loopback, multicast, testnets RFC 5737) безусловно сбрасывается (`DROP`). Слушающие порты хоста (SSH, БД, демон Docker, DNS на порту 53) полностью блокируются через `AGY-SANDBOX-IN`, разрешая только ранее установленные сессии (`ESTABLISHED,RELATED`). Резолвинг DNS выполняется напрямую через защищенные внешние апстримы Quad9 (`9.9.9.9`, `149.112.112.112`).
- **Защита Fail-Closed (маркер готовности):** Запуск контейнеров строго требует полностью поднятой и изолированной сети хоста. Скрипт `ensure-network.sh` создает маркер `/run/agy-sandbox/network.ready` только после успешного применения и проверки всех правил Netfilter и RPDB. Как CLI-инициализатор (`init-sandbox.sh`), так и директива `initializeCommand` в Dev Container прерывают запуск в режиме Fail-Closed, если маркер или правила маршрутизации отсутствуют.
- **Двухуровневая маршрутизация политик ядра Linux (RPDB):** Правила маршрутизации строго привязаны к входящему интерфейсу (`iif agy0`), что гарантирует защиту от утечек трафика даже при активных split-tunnel VPN, переопределяющих таблицу main хоста. Отключено межконтейнерное взаимодействие (`enable_icc=false`), а любые обращения к приватным и специальным CIDR назначения сбрасываются с приоритетом 100 (`unreachable`).
- **Предсобранный оффлайн-патчер и Supply Chain Pinning:** При сборке Docker-образа внешние зависимости фиксируются неизменяемыми хэшами (`ghcr.io/astral-sh/uv` по sha256, `QNIX-Dev/eligibility-antigravity-patcher` по коммиту `90498f50353d414232f593dffe88899bc80b6312`). Патчер предварительно устанавливается в защищенный системный каталог `/usr/local/share/agy-sandbox/patcher` (владелец `root:root`). При старте контейнера `setup.sh` применяет патчер полностью автономно без `git clone` и без доступа к сети.
- **Блокировка проброса учетных данных хоста, сокетов и IPC (VULN-04 & NEW-05):**
  - *Настройки хоста vs контейнера:* Опции `dev.containers.copyGitConfig`, `dev.containers.dockerCredentialHelper`, `dev.containers.mountWaylandSocket` и `dev.containers.forwardGpg` считываются расширением Dev Containers на стороне **хоста** до старта контейнера. В руководстве и скрипте `diagnose.sh` автоматизирован аудит User Settings хоста (`~/.config/Code/User/settings.json`) с проверкой отключения этих параметров на хосте.
  - *Эшелонированная нейтрализация в контейнере:* В `remoteEnv` занулены переменные `SSH_AUTH_SOCK`, `VSCODE_GIT_IPC_HANDLE`, `WAYLAND_DISPLAY`, `VSCODE_IPC_HOOK_CLI`, а утилиты askpass перенаправлены на `/bin/false`.
  - *Обезвреживание сокетов и ликвидация окна гонки (`postAttachCommand`):* Как при старте контейнера (`postStartCommand`), так и при каждом переоткрытии окна редактора (`postAttachCommand` при `Reload Window`) выполняется принудительная очистка и разоружение всех проброшенных сокетов: сокеты Wayland (`vscode-wayland-*.sock`) переводятся в режим `chmod 000` (блокируя доступ на подключение даже при наличии bind-mount), сокеты `gpg-agent` (`S.gpg-agent*`) и IPC (`vscode-ipc-*.sock`) удаляются и блокируются `chmod 000`, файл Docker-кредов `~/.docker/config.json` удаляется.
  - *Сохранение работоспособности Git:* Для сохранения возможности делать `git commit` внутри песочницы из скопированного хостового `~/.gitconfig` вычищаются только чувствительные секции (`credential`, `http`, `core.sshCommand`, `gpg`), а `user.name` и `user.email` сохраняются. Настройка `safe.directory` вынесена в стандартный файл конфигурации `/home/vscode/.config/git/config`, не перезаписываемый хостом.
  - *Запрет автопроброса портов:* В `customizations.vscode.settings` зафиксированы `"remote.autoForwardPorts": false` и `"remote.restoreForwardedPorts": false`, исключающие авто-публикацию портов контейнера на `127.0.0.1` хоста.
- **Харденинг systemd-сервиса:** Исполняемые скрипты и файл конфигурации копируются в каталог `/usr/local/lib/agy-sandbox/`, принадлежащий `root:root` с правами только для чтения (`0755`/`0644`), что исключает уязвимость локального повышения привилегий (LPE). Сервис связан с Docker (`PartOf=docker.service`, `WantedBy=... docker.service`), что гарантирует восстановление изоляции при любых перезапусках демона Docker. Сервис запускается с параметрами изоляции `ProtectHome=yes`, `ProtectSystem=full`, `PrivateTmp=yes` и управляет рантайм-директорией `/run/agy-sandbox`.
- **Динамический Docker IPAM без конфликтов:** По умолчанию подсети выделяются автоматически штатным механизмом Docker IPAM из бесконфликтного пула (`172.17.0.0/16`-`172.31.0.0/16`), с возможностью явного принудительного задания статического CIDR через `sandbox.conf`.
- **Изолированный dual-DNS (`9.9.9.9`, `149.112.112.112`):** Запросы резолвятся напрямую через пару Quad9-серверов в обход резолвера хоста, что исключает утечки DNS и сканирование локальных хостов через NetBIOS/mDNS.
- **Сброс сетевых и системных привилегий и отказ от sudo:** Контейнер является строго непривилегированным (пользователь `vscode`, UID 1000). Пакет `sudo` и конфигурационные файлы `/etc/sudoers*` полностью удалены из базового образа при сборке. Контейнер запускается с обязательными опциями `--security-opt=no-new-privileges:true` и сбросом capability `CAP_NET_RAW`, что исключает атаки на ядро, манипуляции с raw-сокетами, подмену ARP или повышение привилегий до root внутри контейнера.
- **Обязательная валидация `jq` (Fail-Closed):** Генерация конфигурации Dev Container (`init-sandbox.sh`) строго требует наличия утилиты `jq` на хосте. Попытка сборки без `jq` немедленно завершается с ошибкой (код 1), предотвращая деградацию рубежей защиты и пропуск маунтов безопасности.
- **Валидация целевой директории по черному списку хоста (VULN-05 & NEW-03):** Целевая директория песочницы (`target_dir`) и пути дополнительных маунтов (`--mount`) валидируются с раскрытием символических ссылок (`realpath -m`). Блокируется корень файловой системы (`/`), системные директории (`/etc`, `/usr`, `/proc`, `/sys` и др.), корень домашнего каталога пользователя (`$HOME` / `~`), любые родительские каталоги (`/home`, `/Users` и предки `$HOME`), любые скрытые файлы/каталоги в корне `$HOME` (`~/.ssh`, `~/.gnupg`, `~/.aws`, `~/.bashrc` и др.), а также запятые в путях маунтов и защищенные системные пути контейнера. При этом любые проектные подкаталоги в `$HOME` (`~/projects/my-app`, `~/code/...`) и внешние рабочие пространства полностью разрешены.
- **Универсальный харденинг кастомных шаблонов (Full Custom Mode & OPEN-03):** При использовании кастомного шаблона (содержащего `devcontainer.json` и/или `Dockerfile`) инициализатор гарантирует соблюдение единого базового уровня безопасности: если шаблон содержит только `Dockerfile`, автоматически развертывается защищенный базовый `devcontainer.json`; в любой `devcontainer.json` безусловно инжектируются флаги `--security-opt=no-new-privileges:true`, нейтрализация askpass/IPC, read-only маунт каталога `.devcontainer`, Fail-Closed проверка `initializeCommand` и лимиты ресурсов хоста, а флаги `privileged: true`, `capAdd`, `--privileged` и `--cap-add` безусловно вырезаются.
- **Защита бинарника от модификации:** Для зафиксированных версий (`AGY_VERSION != latest`) права на `agy` фиксируются на чтение и выполнение (`chmod 555`), а автообновление блокируется переменной `AGY_CLI_DISABLE_AUTO_UPDATE=1`. При использовании версии `latest` сохраняются стандартные права (`chmod 755`) и штатные автообновления.
- **Двухуровневая модель хранения и общий кэш пакетов (VULN-02 & NEW-04):** Общая глобальная конфигурация (токены авторизации, общие настройки, ID инсталляции) может сохраняться в Docker-томе (`agy-shared-config -> /home/vscode/.gemini-shared`). При создании песочницы авторизационные файлы копируются независимыми копиями (Copy-on-Initialize, без симлинков), исключая межконтейнерное выполнение кода. Конфигурация MCP (`config/mcp_config.json`) строго изолирована для каждого проекта. При первом онбординге токенов (запуск с `--shared-config rw`) утилита `agy-sync-auth` позволяет синхронизировать полученные токены в общий том. Для полностью недоверенных репозиториев рекомендуется `--shared-config isolated`. Общий кэш пакетов (`agy-shared-cache -> /home/vscode/.cache`) сохраняет колеса `uv` и архивы CLI. Проектный контекст (история диалогов, граф brain, локальные базы) изолирован в томе `agy-gemini-data-${localWorkspaceFolderBasename}-${pathHash}`.
- **Защита конфигурации `.devcontainer`:** Каталог `.devcontainer` монтируется внутрь контейнера исключительно в режиме Read-Only (`type=bind,readonly`), исключая изменение скриптов инициализации и настроек контейнера изнутри запущенной песочницы.

## Быстрый старт: подключение к проекту

### Инициализатор agy-sandbox (TUI / CLI)

Развертывание песочницы в целевом репозитории:

```bash
# Клонировать репозиторий песочницы
git clone https://codeberg.org/Retr0xCC/antigravity-sandbox.git ~/.antigravity-sandbox

# Установить команду 'agy-sandbox' в ~/.local/bin
~/.antigravity-sandbox/scripts/init-sandbox.sh --install-bin

# Интерактивный режим (TUI):
agy-sandbox

# Либо инициализация напрямую через аргументы:
agy-sandbox /path/to/project
agy-sandbox /path/to/project [шаблон]
agy-sandbox /path/to/project [шаблон] -v 1.5.3
```

#### Рекомендуемая настройка VS Code / Cursor на хосте (Zero-Trust)

Поскольку расширение Dev Containers считывает параметры проброса сокетов и файлов конфигурации на стороне **хоста** до старта контейнера, рекомендуется добавить следующие директивы в глобальные настройки редактора на хосте (`F1 -> Preferences: Open User Settings (JSON)`):

```json
{
  "dev.containers.copyGitConfig": false,
  "dev.containers.dockerCredentialHelper": false,
  "dev.containers.mountWaylandSocket": false,
  "dev.containers.forwardGpg": false
}
```

Скрипт `diagnose.sh` автоматически сканирует настройки VS Code / Cursor на хосте и сообщает о статусе этих параметров.

#### Режим полной изоляции репозитория (Isolated Sandbox Clone, `--worktree` / `--isolate`)

При разработке в существующих репозиториях предоставление автономному агенту прямого доступа на запись в рабочее дерево проекта несет существенные риски: скомпрометированная модель может изменить сборочные скрипты, конфигурации или git-хуки, которые затем могут быть запущены разработчиком на хосте.

Флаг `--worktree` (синонимы: `--isolate`, `--clone`) обеспечивает строгую физическую изоляцию на основе автономного локального Git-клона с VFS Read-Only защитой метаданных:

* **Полная физическая изоляция основного репозитория (Fix VULN-01):** Вместо небезопасного разделения каталога `.git` (как в традиционном `git worktree`, где подмена `.git` или порча `refs/heads/main` приводила к Host RCE), песочница развертывается как **автономный клон репозитория** (`<repo>-sandbox`) на ветке `agy-sandbox` с флагом `--no-hardlinks`. Каталог основного репозитория хоста **вообще не монтируется в контейнер** (0% поверхности атаки на ветку `main`, историю коммитов, индекс и подмодули хоста).
* **Исключение Hardlink-атак (`--no-hardlinks`):** Клонирование без жестких ссылок гарантирует, что объекты Git в песочнице имеют независимые inode файловой системы и физически изолированы от файлов хоста.
* **VFS Read-Only защита метаданных Git:** Каталоги `.git/hooks`, `.git/info` и файл `.git/config` внутри песочницы монтируются ядром Linux в режиме `readonly`. Это физически блокирует попытки контейнера изменить конфигурацию Git (директивы `core.fsmonitor`, `core.hooksPath`, `core.sshCommand`) или внедрить вредоносные Git-хуки.
* **Исключение конфигурации:** Каталог `.devcontainer/` автоматически добавляется в `.git/info/exclude` песочницы, исключая попадание настроек контейнера в коммиты.
* **Безопасный рабочий процесс и ревью (Workflow):**
  1. Инициализируйте песочницу: `agy-sandbox --worktree /path/to/project`
  2. Откройте директорию песочницы: `code /path/to/project-sandbox`
  3. Переоткройте в контейнере (`F1` -> `Dev Containers: Reopen in Container`).
  4. Позвольте Antigravity выполнять задачи кодогенерации внутри песочницы.
  5. На хосте безопасно проверьте изменения одной командой:
     ```bash
     agy-sandbox --review /path/to/project agy-sandbox
     ```
     (или вручную: `cd /path/to/project && git fetch /path/to/project-sandbox agy-sandbox && git diff HEAD..FETCH_HEAD`).
     Поскольку забор изменений происходит исключительно по транспортному протоколу Git (`upload-pack`), Git на хосте переносит только объекты коммитов и никогда не считывает и не исполняет конфигурацию или хуки из песочницы.
  6. Примите проверенные изменения:
     ```bash
     cd /path/to/project && git merge FETCH_HEAD
     ```

#### Безопасные кастомные маунты (`--mount`)

Если для работы проекта требуются дополнительные датасеты или общие каталоги вне репозитория, используйте флаг `--mount` (можно указывать несколько раз):

```bash
# Режим по умолчанию: Read-Only (:ro)
agy-sandbox --mount /var/data/shared:/data:ro /path/to/project

# При пропуске режима автоматически применяется Read-Only с информационным уведомлением:
agy-sandbox --mount /var/data/shared:/data /path/to/project

# Явный режим чтения и записи (используйте осмотрительно):
agy-sandbox --mount /var/data/output:/output:rw /path/to/project
```

**Ограничения безопасности (Blacklist):**
Для предотвращения эскалации привилегий и компрометации хоста инициализатор строго запрещает монтирование:
* Корневой файловой системы (`/`);
* Системных каталогов хоста и любых их поддиректорий: `/etc`, `/usr`, `/var`, `/bin`, `/sbin`, `/lib`, `/lib64`, `/proc`, `/sys`, `/dev`, `/run`, `/root`;
* Сокетов демона Docker (`/var/run/docker.sock`, `/run/docker.sock`);
* Домашнего каталога пользователя (`$HOME`) целиком;
* Чувствительных каталогов внутри `$HOME`: `.ssh`, `.gnupg`, `.aws`, `.kube`, `.config`, `.docker`, `.local` (и любых их поддиректорий).
Попытка указать запрещенный путь немедленно прерывает выполнение с фатальной ошибкой безопасности.

#### Фиксация версий Antigravity CLI и патчинг

По умолчанию песочницы развертываются с зафиксированной стабильной версией CLI (`1.5.3`), что исключает непредвиденные поломки из-за обновлений upstream, и применяют патч `QNIX-Dev`.

* **Централизованное управление через `scripts/sandbox.conf` (SSOT):** Параметры `AGY_VERSION`, `AGY_PATCH`, `AGY_PINNED`, `PATCHER_REPO` и `PATCHER_COMMIT` настраиваются в `sandbox.conf`. При фиксации версии (`AGY_VERSION != latest`) песочница автоматически защищает бинарник от перезаписи (`chmod 555`) и отключает автообновления (`AGY_CLI_DISABLE_AUTO_UPDATE=true` в `~/.bashrc`). Для версии `latest` сохраняются стандартные права (`chmod 755`) и штатное автообновление.
* **Автоматический Pinning («без упоминания pinning»):** Если переменная `AGY_PINNED` оставлена пустой (`""`), pinning включается автоматически вместе с патчем (`AGY_PATCH="true" -> AGY_PINNED="true"`), исключая поломку патча обновлением upstream. При отключении патча (`--no-patch` или `AGY_PATCH="false"`) pinning автоматически отключается (`AGY_PINNED="false"`), и по умолчанию выбирается чистый официальный `latest` с разрешенными автообновлениями.
* **Принудительное управление Pinning:** Флаги `--pin` и `--no-pin` (или задание `AGY_PINNED="true"` / `"false"` в `sandbox.conf`) позволяют явно переопределить автоматическое поведение (например, зафиксировать чистую версию `1.5.3` без патча через `--no-patch --pin`).
* **Выбор версии патчера:** Версия патчера жестко фиксируется по SHA коммита через `PATCHER_COMMIT` в `sandbox.conf` или флаг `--patcher-commit <sha>`, гарантируя неизменяемость цепочки поставок (Supply Chain Pinning).
* **Интерактивный TUI и CLI:** Мастер позволяет интерактивно выбрать версию (`stable 1.5.3`, `latest`, произвольный тег) и включить/выключить патчер. В CLI доступны флаги `-v, --agy-version <тег>`, `--pin`, `--no-pin`, `--no-patch` и `--patcher-commit <sha>`.

#### Межконтейнерная изоляция и защита от общих томов (Fix VULN-02)

При работе с несколькими проектами (особенно с недоверенным внешним кодом) использование общих Read-Write томов создает риски межконтейнерного выполнения кода (Cross-Sandbox RCE) и отравления кэша. В архитектуре песочницы реализован многоуровневый барьер:

* **Изоляция конфигурации MCP (`config/mcp_config.json`):** Файл `mcp_config.json` исключен из общего тома и сохраняется строго внутри изолированного проектного тома `~/.gemini/config/`. Это полностью исключает инъекцию внешних MCP-серверов в другие песочницы.
* **VFS Read-Only монтирование общего конфига (`SHARED_CONFIG="readonly"`):** Том `agy-shared-config` монтируется ядром Linux в `/home/vscode/.gemini-shared` в режиме только для чтения (`readonly`). Авторизационные токены копируются в проектный том при создании контейнера (паттерн Copy-on-Initialize), позволяя контейнеру обновлять свои сессионные файлы локально без возможности модификации глобального тома.
* **Криптографическая верификация релизов Antigravity CLI (SHA256):** Скрипт `install-agy.sh` проверяет контрольные суммы SHA256 как для скачиваемых архивов, так и для кэшированных файлов в `/home/vscode/.cache/agy-downloads`, предотвращая подмену бинарников в кэше.
* **Изоляция пакетного кэша (`SHARED_CACHE="false"`):** По умолчанию каждый проект получает собственный изолированный том кэша (`agy-cache-<project>-<hash>`), устраняя угрозу межпроектного отравления пакетов (UV/pip wheel cache, go build cache, npm).
* **Исключение коллизий проектных томов:** Имя проектного тома формируется как `agy-gemini-data-<folder_basename>-<path_hash>`, где `<path_hash>` вычисляется на основе канонического пути на хосте. Проекты с одинаковым именем папки в разных путях гарантированно изолированы друг от друга.

Доступные профили шаблонов:
- `default` (по умолчанию) — Базовое чистое окружение: antigravity-cli, uv, git и стандартный набор утилит сборки.
- `affine-mcp` — Профиль для интеграции с AFFiNE Cloud и внешними инстансами через MCP (Node.js 22 LTS, affine-mcp-server 3.11.0, интерактивный мастер `affine-setup`).
- `rpi-edge-node` — Профиль для автоматизации граничных узлов и шлюзов с Ansible (2.18+), `ansible-lint`, `yamllint`, коллекцией `community.general`, Go (1.22+), клиентом OpenSSH и расширениями VS Code (`redhat.ansible`, `golang.go`, `redhat.vscode-yaml`, `even-better-toml`, `samuelcolvin.jinjahtml` для шаблонов Jinja2 `.j2`).
- `math-labs` — Профиль для математических вычислений и анализа данных с Python, Jupyter (`ms-toolsai.jupyter`), просмотрщиком PDF (`tomoki1207.pdf`), NumPy, SciPy, Matplotlib, SymPy и pandas.

### Конфигурация (`scripts/sandbox.conf` и переменные окружения)

Сетевой стек песочницы использует единый централизованный конфигурационный файл `scripts/sandbox.conf` как Single Source of Truth (SSOT). При установке в качестве системного сервиса файл копируется в `/usr/local/lib/agy-sandbox/sandbox.conf`.

```bash
sudo NETWORK_NAME="custom_net" BRIDGE_NAME="cbr0" /usr/local/lib/agy-sandbox/ensure-network.sh
```

### Харденинг systemd-сервиса и защита Fail-Closed

- **Защита от повышения привилегий (LPE):** При выполнении `sudo agy-sandbox service install` все скрипты и `sandbox.conf` копируются в `/usr/local/lib/agy-sandbox/`, принадлежащий пользователю `root:root` с правами доступа `0755`/`0644`. Системный юнит `agy-sandbox-network.service` вызывает скрипты исключительно из этой защищенной директории, исключая модификацию непривилегированным пользователем.
- **Песочница systemd:** Сервис выполняется с директивами `ProtectHome=yes`, `ProtectSystem=full`, `PrivateTmp=yes`, а рантайм-директорией `/run/agy-sandbox` управляет сам systemd.
- **Гарантии Fail-Closed:** Успешный запуск сети создает маркер `/run/agy-sandbox/network.ready` только после верификации всех правил фаервола и маршрутизации. CLI-инициализатор `agy-sandbox` проверяет наличие этого маркера перед сборкой devcontainer или запуском среды.

### Проверка сетевой изоляции

Для комплексного аудита правил Netfilter, таблиц маршрутизации и доступности DNS предусмотрен встроенный диагностический инструмент:

```bash
agy-sandbox diagnose
# Либо прямой запуск скрипта:
~/.antigravity-sandbox/scripts/diagnose.sh
```

Диагностика проверяет 8 комплексных контрольных точек безопасности:
1. **Docker Engine, сеть моста (`agy_net`) и маркер готовности:** Проверка отклика демона Docker, динамическое определение назначенной подсети, сопоставление интерфейса `agy0` и проверка наличия файла `/run/agy-sandbox/network.ready`.
2. **Сетевой интерфейс ядра (`agy0`):** Подтверждение существования интерфейса моста и его состояния в ядре.
3. **Маршрутизация политик ядра Linux (`ip rule`):** Проверка правил приоритета 100 `unreachable` для всех 15 приватных/специальных диапазонов IPv4 (включая RFC 5737 testnets), строго привязанных к интерфейсу `iif agy0`, и отсутствия внутриподсеточных обходов.
4. **Фильтрация пакетов Netfilter (`iptables` / `ip6tables`):** Проверка переходов в кастомные цепочки `AGY-SANDBOX-FWD` и `AGY-SANDBOX-IN`, блокировок DROP для всех 15 диапазонов и полной блокировки доступа к портам хоста (включая порт 53).
5. **Рубеж IPv6 и персистентность Systemd:** Аудит отключения IPv6 (`disable_ipv6` на `agy0`), доступность ip6tables и подтверждение неизменяемости файлов сервиса в `/usr/local/lib/agy-sandbox/`.
6. **Supply Chain Pinning и целостность образа:** Проверка неизменяемого sha256 хэша для `uv`, пиннинга коммита патчера, непривилегированных прав на тома, защищенного размещения скриптов в `/usr/local/share/agy-sandbox/` и поддержки `safe.directory` для git worktree.
7. **Спецификация Dev Container и рантайм-харденинг:** Статический аудит флагов блокировки учетных данных хоста, нейтрализации Askpass/IPC, Fail-Closed проверки `initializeCommand`, параметров безопасности `runArgs`, readonly-маунта `.devcontainer` и флагов CLI (`--worktree`, `--mount`).
8. **Проверка границ контейнера и активные зонды:** Инспекция запущенного контейнера (`no-new-privileges`, сброс capability `NET_RAW`, лимит pids), Read-Only маунтов метаданных Git (`hooks`, `config`, `info`) и зондирование сетевых рубежей TCP-сокетами без привилегий.

### Очистка остаточных контейнеров (`agy-sandbox --clean`)

При отладке или пересборках Dev Container в Docker могут накапливаться зависшие (`Created`, `Dead`) или осиротевшие контейнеры от удаленных папок. При этом обычные остановленные проекты (`Exited`), к которым вы планируете вернуться позже, **не удаляются без вашего согласия**.

В `antigravity-sandbox` встроен интерактивный инструмент выборочной очистки:

```bash
# Интерактивное меню с выборочным списком контейнеров:
agy-sandbox --clean

# Удалить ТОЛЬКО мусор и осиротевшие контейнеры (папки которых уже удалены с диска):
agy-sandbox --clean --orphaned

# Предварительный просмотр без удаления (Dry-Run):
agy-sandbox --clean --dry-run

# Полная очистка всех остановленных контейнеров и промежуточных слоев образов:
agy-sandbox --clean --all -f
```

Также режим доступен в TUI-меню `agy-sandbox` в пункте `[4] 🧹 Prune Residual Containers & Artifacts`. Утилита наглядно группирует контейнеры:
* **Active (Running):** работающие проекты — гарантированно защищены.
* **Stopped (Exited):** закрытые проекты, чьи папки существуют на хосте — предлагаются в интерактивном списке с номерами (можно выбрать, какие удалить, а какие оставить).
* **Defunct / Orphaned:** сломанные сборки и контейнеры от уже удаленных папок — очищаются безопасно.

### Жизненный цикл контейнера (setup.sh)

Скрипт первичной настройки `setup.sh` предустановлен в системный каталог `/usr/local/share/agy-sandbox/setup.sh` и выполняется один раз при создании контейнера (`postCreateCommand`):
* выставляет корректные непривилегированные права на тома `/home/vscode/.gemini` и `/home/vscode/.gemini-shared`;
* безопасно регистрирует целевую рабочую директорию в `git config safe.directory`, корректно разрешая ссылки `gitdir:` в случае git worktree без использования небезопасных масок (`safe.directory "*"`);
* запускает автономный патчер `/usr/local/share/agy-sandbox/patcher/manager.py` полностью в оффлайн-режиме без скачивания внешнего кода;
* фиксирует бинарник от изменений (`chmod 555`) при зафиксированной версии или сохраняет `chmod 755` для `latest`;
* очищает проброшенные сокеты аутентификации и скопированные учетные данные хоста;
* создает маркер `/home/vscode/.agy_initialized`, предотвращая повторное выполнение при перезапусках.

## Модель безопасности и остаточные риски

### Что закрыто на 100% (Zero-Trust Guardrails)

Antigravity Sandbox реализует многоуровневую глубоко эшелонированную защиту:

| Вектор атаки | Механизм защиты | Уровень защиты |
| :--- | :--- | :--- |
| **Сканирование локальной сети (LAN) и интранета** | Маршрутизация ядра RPDB (`iif agy0` приоритет 100 `unreachable`) и Netfilter `AGY-SANDBOX-FWD` DROP | **100% Заблокировано** (на уровне ядра) |
| **Кража метаданных облака (`169.254.169.254`)** | Явный сброс маршрутов и фильтрация link-local диапазонов в firewall | **100% Заблокировано** |
| **Доступ к службам хоста (SSH, БД, Ollama, сокет Docker)** | Netfilter `AGY-SANDBOX-IN` DROP на интерфейсе `agy0` (100% портов хоста заблокировано, включая порт 53; DNS направляется на внешние Quad9) | **100% Заблокировано** |
| **Утечка учетных данных хоста, сокетов (SSH, Git, Wayland, GPG) и IPC** | Очистка и разоружение сокетов (`chmod 000` для Wayland/GPG/IPC) на `postStartCommand`/`postAttachCommand`, очистка `.docker/config.json`, санация `~/.gitconfig` с сохранением `user.name`/`user.email`, обнуление `remoteEnv`, отключение `remote.autoForwardPorts`, аудит настроек хоста в `diagnose.sh` | **Нейтрализовано в контейнере / Рекомендуются настройки хоста** |
| **Повышение привилегий до root внутри контейнера** | Полное удаление `sudo` и `/etc/sudoers*` из образа, принудительный флаг `--security-opt=no-new-privileges:true`, вырезание `privileged: true` и `capAdd` в Full Custom Mode | **100% Исключено** (Rootless) |
| **Побег из контейнера и эксплуатация уязвимостей ядра** | `--security-opt=no-new-privileges:true`, `--cap-drop=NET_RAW`, непривилегированный пользователь `vscode`, лимиты pids/memory/cpus | **Защищено** |
| **Модификация конфигурации контейнера и Host RCE** | Read-Only bind-маунт каталога `.devcontainer/` внутрь контейнера, принудительный фильтр безопасности даже в Full Custom Mode | **100% Защищено** |
| **Атаки на цепочку поставок при сборке образа** | Фиксация digest `uv` (`sha256:32a...`), фиксация коммита патчера (`90498f50353d`), предсобранный оффлайн-патчер в `/usr/local/share/agy-sandbox/patcher` (root:root) | **100% Неизменяемо** |
| **Внедрение вредоносных Git hooks / Git config / tasks.json (режим `--worktree`)** | Изолированный клон репозитория (`--worktree`), Read-Only маунты на `.vscode/`, `.git/modules`, `.git` указатель и исключение прямого монтирования `.git` хоста | **100% Защищено** (Изолированный клон) |
| **Случайное монтирование $HOME или системных каталогов хоста** | Черный список `validate_target_dir` и `validate_and_parse_mount` с раскрытием симлинков (`realpath -m`), блокировка `/home`, `/Users`, корня `$HOME`, `/`, dotfiles и системных путей | **100% Заблокировано** |

### Остаточный риск (Прямое монтирование БЕЗ `--worktree`)

> [!WARNING]
> При запуске песочницы напрямую в основном репозитории хоста **без** флага `--worktree` контейнер имеет прямой доступ на запись в файлы вашего проекта.

Если проект содержит исполняемые файлы, сборочные скрипты или конфигурации IDE:
* `Makefile`, `build.sh`, `configure`
* `package.json` (`scripts`, `preinstall`, `postinstall`)
* `.vscode/tasks.json` или `.vscode/launch.json`
* Конфигурации сборки Python (`setup.py`, `pyproject.toml`)

Галлюцинирующий или скомпрометированный агент может модифицировать эти файлы внутри контейнера. Если вы впоследствии запустите команду `make`, `npm test` или выполните задачу VS Code на хост-системе вне песочницы, вредоносный код будет выполнен на хосте с вашими правами!

**Рекомендация и митигация:**
* Для непроверенного кода, внешних репозиториев, автономных запусков агента или чувствительных сред **ВСЕГДА используйте режим `--worktree`**:
  ```bash
  agy-sandbox --worktree /path/to/project
  ```
* В режиме `--worktree` любые изменения агента физически изолированы в каталоге `<repo>-sandbox` и отдельной ветке Git. Кроме того, хостовые `.git/hooks` и `.git/config` защищены VFS-маунтами в режиме «только чтение».
* Никогда не сохраняйте открытые боевые токены, `.env` файлы с продакшн-паролями или приватные ключи внутри рабочей директории проекта перед запуском песочницы.

## Создание собственных шаблонов

`antigravity-sandbox` поддерживает два формата создания шаблонов:

### 1. Декларативный режим (рекомендуется)

Вместо дублирования базовых файлов `Dockerfile` и `setup.sh`, достаточно создать каталог `templates/<имя_шаблона>/` только с необходимыми манифестами:

- **`packages.txt`** *(опционально)* — системные пакеты для установки через `apt-get` (по одному на строку, поддерживаются комментарии `#`).
- **`extensions.txt`** *(опционально)* — идентификаторы расширений VS Code (например, `golang.go`, `ms-python.python`).
- **`settings.json`** *(опционально)* — параметры конфигурации редактора, объединяемые с `customizations.vscode.settings`.
- **`extra.Dockerfile`** *(опционально)* — дополнительные сборочные инструкции для образа (например, `uv tool install ...`).
- **`extra-setup.sh`** *(опционально)* — bash-команды, выполняемые при первичной инициализации контейнера.
- **`description.txt`** *(опционально)* — краткое описание для справки CLI (`--list`) и меню TUI (по умолчанию: `Custom sandbox profile`).

Инициализатор песочницы автоматически наследует базовую конфигурацию (`base/Dockerfile`, `base/setup.sh`, `base/devcontainer.json`), объединяя её с манифестами шаблона.

### 2. Режим полной конфигурации (Full Custom Mode)

Если требуется полностью переопределить среду сборки, поместите собственные файлы `devcontainer.json` и/или `Dockerfile` напрямую в каталог `templates/<имя_шаблона>/`. Инициализатор скопирует их в целевой проект без объединения с базовым слоем.
